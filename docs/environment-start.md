# Starting a CryptKeep cloud task

The repository uses TypeScript, Three.js, Vite, Vitest, and Playwright Test. The current slice includes seeded generated-floor exploration, first-person movement, mouse look, sprint, dash, pause/resume, live sword combat, resource HUD and damage feedback. Generated floors have no enemies yet; development includes a labeled native-input training room.

For a new task:

1. Read `CONTEXT.md`, `SPEC.md` Section 0, `REVIEW.md`, the assigned task card and its accepted prerequisite handoffs/review reports. Respect the coordinator/Luna task boundaries; the specification does not itself authorize implementation. A request to start a task or milestone authorizes that scoped work and its independent Luna review/repair workflow (maximum three rounds per task).
2. Use the existing `/workspace/CryptKeep` checkout. Cloud tasks already have isolated environments; do not create a Git worktree unless the owner explicitly requests one. Run `cd /workspace/CryptKeep` before repository commands.
3. Dependencies may already be present in the prepared cloud snapshot; check rather than assuming every new environment is ready. If `node_modules` is missing, run `bash /workspace/CryptKeep/tools/cloud-install.sh`; it uses `npm ci` and keeps npm's cache in `/workspace/.cache/cryptkeep/npm`.
4. Run `npm run verify:environment` to validate the installed toolchain. This checks generated temporary fixtures, not game behavior. On 2026-10-06, CK-00-01 measured Node.js `v24.19.0`, npm `11.9.0`, and system Chromium `151.0.7922.173`; `npm ls --depth=0` and the package-lock top-level versions matched all eight declared packages. Dependencies were already installed, so no install was needed.
5. Start `npm run dev -- --host 0.0.0.0 --port 5173 --strictPort` to serve the preview. Run `npm run verify` for the combined app workflow: typecheck, unit tests, build, then browser checks. It stops on the first failure. `npm test` covers deterministic clock, RNG, input, and event behavior, then runs Node tooling tests that start real child processes and check stage ordering, failures, missing executables, and signals. `test:e2e` performs its own production build, so `verify` builds twice; it starts dev and preview servers on separate ports, and checks shell rendering, renderer lifecycle, browser error capture, and production behavior. These checks validate the current preview and tooling, not playable gameplay.

In the app, enter a seed and choose **Generate dungeon** to replace floor 1. Choose **Explore dungeon** to capture the mouse, then use WASD and mouse look to explore. Hold Left Shift while moving to sprint. Press Space for a collision-safe dash in normalized movement direction (or facing direction with no movement input): it costs 25 stamina once, travels up to 2.2 m over 0.22 seconds, and has a 0.8 second cooldown and a 0.1 second evasion window. First wall contact ends the dash. Left click taps a light sword swing; holding and releasing charges a heavier swing. Both share the same stamina used by sprint and dash. Stamina regenerates after 0.65 seconds idle; mana regenerates after 1 second idle. Escape, window blur, a hidden page, editable control focus, or native lock loss pauses the player immediately, clears held input and pending sword charge, and freezes floor ticks, pose, resources, regeneration timers and dash cooldown. A minimal accessible **Resume** panel gives the pause reason. Resume uses the focused button's click/Enter/Space gesture to request native capture; gameplay and the same floor clock resume only once capture succeeds. Returning focus or visibility never resumes automatically. A canceled native request must settle before another gesture can request capture. In development, **DEV TRAINING** loads a hand-built clear-target room or wall-blocked variant, separate from generated floors. The existing seed and Generate controls remain available beside the pause panel; rerolling replaces the floor and leaves play paused until a fresh Resume gesture. Keep the forwarded Vite server running while using the browser.

Verify server readiness with `curl -fsS http://127.0.0.1:5173/`; the Playwright suite starts Vite automatically. The shared harness registers listeners before navigation and fails with captured page/console error messages. In development, `window.__cryptkeepDiagnostics.snapshot()` returns immutable readiness, render counts, generated or diagnostic world details, player resources/input and detached combat state; it is removed on page teardown. Production tests check that this global and the training controls are absent even with diagnostic-looking query parameters. Browser checks cover floor generation, movement, native mouse look, renderer cleanup and trusted native sword input against the DEV training target. These checks establish M03 combat integration, not generated enemies or campaign completion.

The world renderer exclusively owns the WebGL2 context passed to it and retires that context when disposed. A later renderer instance must use a fresh canvas and WebGL2 context; the renderer leaves canvas DOM ownership with the application shell.

`npm run verify:environment` separately checks generated temporary fixtures and is evidence of toolchain operation only; it is not part of real-app verification. The environment check uses the preinstalled `/usr/bin/chromium`. To select another compatible Chromium binary, set `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` to its path. No Playwright browser download is required.

Check the current execution permission profile before starting local servers or network commands. The current M03 managed sandbox denies loopback binding with EPERM and automatically rejects network permission overrides; do not retry those grants or bypass inherited proxies/network policy. Historical network-enabled setup below passed in an earlier profile. For this profile, use the exact-source hosted verification procedure in [M03-hosted-verification.md](../decisions/M03-hosted-verification.md); successful browser proof comes from GitHub Actions, not a claimed local preview. Preserve inherited cloud proxy/CA settings and destination policy.

CK-00-01 ran `npm run verify:environment` with the network-enabled sandbox grant. All five generated-fixture checks passed. Those results establish toolchain operation only. CK-00-02 adds the initial shell and browser checks; these establish shell behavior, not gameplay.

## GitHub Actions verification

`.github/workflows/verify.yml` runs on pushes to `master` and `codex/cryptkeep-m03-review`, pull requests, and manual dispatch. Its single Ubuntu job pins Node.js 24.19.0 and npm 11.9.0 to meet `package.json` engines, installs the exact lockfile with `npm ci`, then provisions Chromium and OS libraries inside the temporary runner with `npx playwright install --with-deps chromium`. It writes `playwright-core`'s resolved Chromium executable path to `GITHUB_ENV`; Playwright keeps using the launch flags from `tools/cloud-browser.json`. The job runs `npm run verify` unchanged, so it covers typecheck, unit and tooling checks, build, and development/production browser checks. No cloud cache path, credential, or secret is used. On failure, the Playwright `test-results/` directory is offered as an artifact, ignored if empty and retained for seven days. Review-branch pushes also upload scoped `test-results/CK-03-*/**` screenshot evidence on success or failure with attempt-specific names; browser downloads and dependency caches are not cached.

The workflow file and command/configuration match passed independent review. Its first hosted [Actions run 37469336633](https://github.com/Guna210/CryptKeep/actions/runs/37469336633) completed successfully on CK-00-10 commit `7421a17`, confirming Node/npm/browser provisioning and the full verify command (25 app tests, 7 tooling tests and 5 browser checks). The CI browser installation is independent of the cloud environment's preinstalled `/usr/bin/chromium` and `/workspace` caches. That first baseline run did not establish gameplay. Final M03 master [run37609661301](https://github.com/Guna210/CryptKeep/actions/runs/37609661301) on receipt4e5142a passed171 app tests and24 browser checks, including native sword controls and pause regressions; it does not establish generated enemies or full campaign completion. The environment check removes its temporary fixture after execution.
