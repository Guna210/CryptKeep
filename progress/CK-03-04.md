# CK-03-04 — Implement sword tap attack timing

**Builder:** `/root/ck_03_04_builder` (GPT-6 Luna)
**Status:** Accepted and pushed after independent round-one PASS.

## Result

Implemented a pure immutable sword adapter in `src/weapons/sword.ts`. A primary press enters anticipation without a cost or attack. An ordered primary release allocates an ID through the supplied runtime context and commits the light attack's 10 stamina through the dispatcher; a rejected spend returns directly to idle. The successful release starts committed windup, followed by active and recovery phases. Timing uses seconds, carries elapsed `dtSeconds` over multiple phase boundaries, and tolerates floating point representation at exact boundaries. A long hold never auto-fires.

The adapter emits exactly one typed `active-hit` request on entering the active phase, with light damage 18 and the committed ID. Later active ticks do not emit duplicate requests. The shared damage resolver can therefore be called once at active onset; target entry during the remainder of the active window is not queried by this adapter. CK-03-05 will add charge behavior. Cancellation clears the weapon to idle without creating a release; committed stamina is owned by the shared dispatcher and is not refunded.

Invalid direct-adapter `dtSeconds` values (non-finite or negative) and malformed state are programmer errors (`RangeError` for time and `TypeError` for state/command). Zero time is valid. Dispatcher updates apply ordered command edges at tick start and then advance the resulting state by the full tick duration.
