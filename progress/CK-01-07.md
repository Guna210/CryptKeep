## Result and scope

Added a batched Three.js floor renderer for accepted `RoleFloorPlan` data. It validates before allocating, covers each walkable cell with one 2m floor and one 2m ceiling instance, emits 3m stone wall faces only on walkable-to-solid boundaries, offsets each 0.16m wall slab completely into the solid cell, and renders raised, differently shaped role markers at the four specified cell centers. `ceilingVisible: false` hides ceiling instances for an overview while retaining the ceiling geometry. Surfaces and walls use instanced meshes; a generated 36×36 sample uses eight owned geometries/instanced meshes and seven renderer draw calls, rather than a mesh per cell. Textures repeat over each 2m cell through the accepted materials and existing nearest filtering.

Changed files: `src/render/floor.ts`, `src/render/floor.test.ts`, `src/render/renderer.ts` (the specifically authorized additive option), `tests/harness/floor-renderer.html`, `tests/harness/floor-renderer.ts`, `tests/e2e/floor-renderer.spec.ts`, two selected captures under `docs/evidence/CK-01-07/`, and this handoff. ## API and ownership

- `createRenderedFloor(plan: RoleFloorPlan, library: MaterialLibrary, options?: { ceilingVisible?: boolean }): RenderedFloor` returns `{ root, counts, dispose }`. Counts report owned geometries, instances and the four markers. Invalid plans reject through the accepted `validateFloor` contract before Three.js allocation.
- World positions use a 2m grid with lower-left cell indexing: tile center `(2x+1, 2z+1)`, floor top `y=0`, ceiling bottom `y=3`, and wall vertical extent `0..3m`. Role marker shapes use `library.materials.entry/boss/reward/exit`.
- Each floor owns every geometry and `InstancedMesh` it constructs. Idempotent `dispose()` detaches and clears its root, disposes every mesh instance buffer and each unique owned geometry once. `MaterialLibrary` materials and textures are borrowed and never disposed by the floor; the library must outlive all its floor borrowers.
- `WorldRendererOptions.includeDiagnosticFixture` is optional and defaults to the accepted diagnostic scene. Setting it to `false` omits only those diagnostic objects; renderer context ownership/disposal is unchanged.
- The isolated browser fixture builds the next floor and library first, then disposes the previous floor before attaching the replacement. It disposes the old library after the old floor and retains one renderer/context for the full 25-cycle lifecycle check.
