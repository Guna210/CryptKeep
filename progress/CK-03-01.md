## Result and interfaces

Added `PhysicalDamageResolver` and typed combat records in `src/combat/damage.ts` and `src/combat/types.ts`. The resolver accepts source identity, an immutable damageable target snapshot, and a physical packet. A successful result returns a detached target with bounded health, actual HP lost, and whether this hit killed it. Callers own adoption of the returned target snapshot into their simulation state.

Packets require nonempty matching source/target/attack IDs, physical damage type, and finite positive amount. Self/friendly packets, identity mismatches, repeated attack-target pairs, and already-dead targets leave health/events unchanged. A runtime resolver instance owns the dedupe ledger: one attack ID can affect several targets once each, and a nonlethal hit consumes that target's entry too. It also retains committed dead target IDs so a different attack against a stale predeath snapshot cannot emit another death event. IDs are unique within a runtime; create a fresh resolver when replacing that runtime (for example, between floors). Positive valid damage has a 1 HP minimum per SPEC 5.1, then clamps to remaining health; damage events report actual HP lost.

Extended the existing `EventCollector` with immutable typed `damage-applied` and `entity-died` variants. Both are copied into frozen tick-stamped records. Successful hits emit one damage event; a lethal hit also emits one death event. Rejected packets emit neither. No player-state module changes, armor/status/critical/reward logic, or app wiring were added.
