## Correction

Added a resolver-instance `deadTargetIds` set. A target ID enters this set when a lethal hit commits, and all subsequent packets for that ID are rejected as `dead-target`, even when the caller supplies a stale predeath health snapshot or a different attack ID. The set is discarded with its resolver; combatant IDs must remain unique within that runtime. Ordinary health remains immutable and callers still adopt the returned target snapshot for nonlethal updates.

Added a regression that resolves two different attacks against the same 1-HP stale snapshot before event flush and confirms one death event. It also checks rejection on a later tick, both with and without an `EventCollector`.
