## Result and scope

Implemented a pure semantic sampler boundary with no browser listeners or raw key-code map. It tracks named held actions, queues ordered valid press/release edges, derives raw keyboard movement axes, accumulates relative look deltas, and reports cancellation reasons separately from normal releases. Calls to `clearInput(reason)` remove held state, queued ordinary edges, movement and look, while appending the reason to a separate ordered cancellation queue. Inputs arriving after the clear are retained for the next sample together with the cancellation report; pre-clear inputs cannot leak into it.

## Contracts for following tasks

- `Action` names are `moveForward`, `moveBackward`, `moveLeft`, `moveRight`, `sprint`, `dash`, `primary`, `secondary`, `interact`, `heal`, `slotOne`, `slotTwo`, `inventory`, `map`, and `pause`. Browser adapters map keys/buttons into these semantic names later.
- `InputSampler.press(action)` ignores duplicate held presses (including key repeat); `release(action)` ignores unmatched ups. Both append a transition only when state changes. `sample()` returns final `held`, convenience `pressed`/`released` arrays, and the canonical ordered `edges` list. Edges and held state are detached snapshots.
- `setDirection(direction, isHeld)` maps movement to the same semantic held/edge state. `movement.x/y` are raw axes in [-1,1]; opposing directions cancel and diagonals remain `(±1, ±1)`. Locomotion should normalize diagonals when converting commands to motion.
- `addLookDelta(x,y)` accumulates finite input. Invalid deltas are ignored. Sampling consumes accumulated deltas once; later catch-up samples see zero unless new look input arrived.
- `clearInput(reason)` accepts `pause`, `blur`, `hidden`, `pointer-lock-lost`, `inventory`, `death`, `victory`, `floor-loading`, `weapon-switch`, or `resource-failure`. Cancellation entries never synthesize released edges. A consumer that requires the distinction between a sword tap and bow release should process `edges` in order and discard uncommitted attacks on the cancellation report.
- Cancellation and edge queues are consumed once per sample. Multiple clear calls preserve cancellation order. Post-clear new input can be included in the same next sample; it is distinguishable from canceled input via the absence of pre-clear edges.

The action vocabulary and semantic API are ready for later pointer/DOM adapters. This task does not implement input capture, key rebinding, gameplay, or consumer wiring.
