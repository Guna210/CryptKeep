## Result and interface

Added a DOM-owned HUD in `src/ui/hud.ts` and `src/ui/hud.css`, plus caller-clock feedback in `src/render/feedback.ts`. `createCombatHud(host, playerId, eventCollector, options)` returns `update(snapshot)`, `advance(dtSeconds, paused?)`, `setDamageFlashesEnabled(enabled)`, `resetFeedback()`, and idempotent `dispose()`. Each immutable snapshot supplies actual health, stamina and mana `ResourceValue`s and a `SwordState`; charge is read through `swordChargeFraction`. The component owns its DOM and one event subscription. The caller retains the collector, actor/resource state and simulation tick, calls `advance` with explicit simulation seconds, passes pause state to freeze timers, updates charge after sword state changes, and can clear feedback when replacing its world. The HUD creates no clock, input listener, damage system or resource pool.

The HUD displays finite bounded numeric text and bars, flags nonzero health at or below 25%, centers a reticle, and clears charge when the sword is no longer held in anticipation. It filters immutable physical damage events by player identity. Relevant events set fixed, nonstacking 0.15-second hit and 0.25-second hurt timers; hurt opacity is capped at 0.22. Repeated events restart those timers. Disabling flashes immediately hides only hurt overlay. Disposal removes the component DOM and subscription and is safe to repeat.

The `tests/harness/hud-fixture.html` development fixture uses `PhysicalDamageResolver`, actual `EventCollector` batches, resource snapshots and accepted sword state selectors. Its buttons only generate explicit test fixture state; they do not claim trusted native sword input. The active-subscription counter proves repeated HUD updates keep one subscription and disposal leaves none.
