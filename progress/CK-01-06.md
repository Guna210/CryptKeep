# CK-01-06 — Generate base pixel materials

## Handoff

Implemented deterministic original base tile recipes for stone, floor, door, entry, boss, reward and exit. `createBaseTile(seed, kind, size?)` returns an immutable recipe record with an RGBA `Uint8Array`; supported dimensions are 16×16 and 32×32, with 32 as default. It rejects unsupported kinds, invalid sizes, and malformed or oversized seeds. Every recipe uses the existing `deriveStream(seed, "cosmetics", "base/<kind>/<size>")` stream, so texture generation cannot advance layout, loot, or other gameplay streams.

`createMaterialLibrary(seed, size?)` owns seven Three.js data textures and seven corresponding material instances. Stone, floor and door use rough `MeshStandardMaterial`; role markers use `MeshBasicMaterial` for readable colors under limited lighting. Textures use RGBA unsigned bytes, nearest minification/magnification, no mipmaps and sRGB color space. Surface tiles repeat; markers clamp. The library's `dispose()` is idempotent and disposes every owned material and texture once. Floors and future render borrowers may reuse the library's material instances but must never dispose borrowed materials or textures; only the library owner calls `dispose()` after all borrowers are removed.

The isolated 2D contact sheet fixture uses actual recipe pixels and creates a library to exercise the same material setup without starting another WebGL engine. Evidence is a reproducible 820×520 screenshot using seed `ck-01-06`, 32×32 recipes, CSS nearest-neighbor enlargement, and the labeled order stone, floor, door, entry, boss, reward, exit at `docs/evidence/CK-01-06/materials.png`.
