## Result

Added a hand-authored 9×9 diagnostic room, explicitly labeled `DEV TRAINING ROOM`. The room is separate from generated campaign floors, and its factory throws outside Vite development and test modes. It exposes an immutable grid/player/target snapshot, living melee colliders, the real `queryMeleeTargets` result, damage application through `PhysicalDamageResolver`, and tick-stamped events through `EventCollector`. Accepted damage adopts the resolver's returned immutable target. Target death retires the collider and resolver rejects later hits; duplicate attack IDs are ignored.

The clear and obstructed variants use the same pose, target, and occupancy grid dimensions. The wall variant marks a solid tile at cell `(4,5)` and verifies the actual query has no hit. Player pose `(10.3, 10.5)` is accepted by `moveCircleOnGrid` with the wall present; the target at `(9.3, 9.6)` with radius `0.35 m` remains clear of solid geometry. The grid is diagnostic test content, not a procedural campaign floor. It is exported as `Grid`; CK-03-09 will need an explicit grid-to-floor collision adapter or a follow-up adapter in its assigned integration scope. The fixture's local event tick advances once per `applyDamage` call; native combat must use the actual simulation tick and live command pose at its integration boundary. This fixture does not claim native mouse/sword input integration.

Added a pixel-textured wood-and-iron training dummy with a health bar, changing health color, visible fallen/dead pose, and idempotent disposal of all owned geometry/material/texture resources. The isolated browser setup in `tests/harness/combat-room.html` places the rendered target at the exported collider coordinates and asserts that parity in Playwright. It provides test controls for light damage, heavy damage, lethal damage, and wall toggling. These controls exercise the fixture only and do not simulate native sword input. No production app module imports the fixture or target renderer.
