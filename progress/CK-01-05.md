## API and behavior

- `validateFloor(plan: unknown)` returns a frozen `{ valid, issues }` result. It validates supported bounds before traversing data, room count/rectangles/interiors, solid border, role markers, entry 5×5 safety, in-room centered disjoint 3×3 pads, arena size/ownership, four reserved paths, exact sorted reservation union, named corridor edges and their walkable 2×2 footprints. A cardinal BFS over actual occupancy must reach every walkable cell and every required marker; graph metadata never substitutes for tile reachability.
- `generateFloor({ campaignSeed, floorNumber, generatorVersion? }, options?)` validates inputs before creating attempt state. It derives a recorded base floor seed and eight isolated deterministic attempt seeds. The default attempt composes `layoutDefaults` → `createFloorPlan` → `placeRooms` → `connectRooms` → `assignRoles` → `validateFloor`; incomplete room placement rejects that attempt. A typed `attemptFactory` test seam receives a frozen context and is never serialized. Malformed outputs, validation failures, and thrown errors each consume one bounded attempt. Success stops immediately; eight failures produce the fallback.
- `GeneratedFloor` contains a detached, deeply frozen `RoleFloorPlan`, frozen diagnostics (`baseFloorSeed`, actual call count, fallback flag, bounded rejection messages, and fallback reason when used), and an FNV-1a content hash. Factory output is validated before copying, and only known schema fields are copied; arbitrary timestamp/UI fields cannot affect the hash or remain in output.
- `createFallbackFloor(seed, floor, version)` builds a solid-border 36×36 four-room layout with seed/floor-derived stable room IDs, real corridors, roles, pads and paths. It must pass `validateFloor` or throws a clear internal error.
