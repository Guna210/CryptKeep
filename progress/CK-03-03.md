# CK-03-03 — Define weapon state/attack adapter contract

**Builder:** `/root/ck_03_03_builder` (GPT-6 Luna)
**Status:** Submitted for independent review; no Git operations performed.

## Result

Added a sword-only current-weapon contract in `src/weapons/types.ts` and `src/combat/weapon-dispatch.ts`. The weapon contract provides immutable simulation state, ordered `GameCommand` updates, explicit cancellation, typed `active-hit` attack requests, and transient `WeaponUpdateContext` service callbacks. Concrete weapon state is generic across the updater and dispatcher so class-specific fields survive the boundary without casts. The shared phase vocabulary includes idle, anticipation, windup, active and recovery. Context callbacks must remain update context and must never be serialized as weapon state.

The dispatcher processes cancellation before update. `InputSampler.clearInput` discards pre-clear edges, so if its next command carries both cancellations and fresh post-clear edges, the dispatcher first cancels the previous state and then processes those fresh edges in their original order. It strips cancellation markers from the transient command passed to `update`; it never manufactures a normal release. Without cancellation, the full ordered edge list reaches the updater, preserving same-tick press/release taps.

Release-time stamina is committed through the adapter callback against the same immutable `ResourceValue` pool supplied by the player simulation. A successful commit replaces stamina, calls `recordStaminaSpend` on the supplied shared `ResourceRegenTimers`, and records the attack ID in runtime-local commitment history. Invalid cost, insufficient stamina, and repeated commitment IDs reject without spending. Active-hit requests must reference their attack ID as the committed cost ID; the dispatcher accepts previously committed IDs on later active ticks without charging again. Cancellation does not refund earlier commitments or damage requests.

Runtime attack IDs use the caller-provided runtime ID and monotonic runtime sequence (`<runtimeId>:<sequence>`). The runtime identity must be unique for the life of a simulation runtime and be replaced with that runtime. Malformed runtime IDs, non-safe/nonnegative sequence counters, duplicate or foreign commitment IDs, IDs that were not issued by the runtime, and invalid time values throw as programmer errors. Invalid costs and inadequate stamina are ordinary rejected transactions. No future-class stubs, sword implementation/tuning, guard/parry, input wiring, rendering, query, or damage execution were added. `PhysicalDamageResolver.resolve(source, target, packet)` remains the later consumer for accepted physical requests.

## Integration signatures inspected

- `PlayerSession.snapshot()` exposes shared player stamina and `ResourceRegenTimers`; its simulation uses `recordStaminaSpend` and `advanceResourceRegeneration`. This dispatcher accepts those same values and does not create an independent weapon pool.
- `PhysicalDamageResolver.resolve(source: CombatantIdentity, target: DamageableCombatant, packet: PhysicalDamagePacket): DamageResult` applies damage later and deduplicates attack/target pairs.
