## Policy and implementation

The adapter now serializes every native pointer-lock request, whether the browser returns a promise or legacy `void`. It retains one physical outstanding request separately from the logical input/capture state. Blur, Escape, hidden-page handling, and lock loss clear inputs and cancel the logical request immediately, while preserving the physical request record until its promise settles or its legacy acquisition/error event arrives.

If another explicit gesture arrives while a canceled native request remains outstanding, the adapter reports `waiting` through its state observer and makes no native request. It does not queue that expired gesture. A canceled late acquisition releases pointer lock only when this surface owns it; the late terminal result returns the adapter to idle. A fresh gesture after settlement starts a new request. Global lock-error events do not settle promise-returning requests because they have no request identifier; their own promise is authoritative. Serialized legacy terminal events cannot be attributed to a later request.

Disposal removes all ordinary listeners immediately. If any legacy void request remains physically outstanding, including one canceled earlier, only the terminal document lock-change/error listeners remain. Unrelated-owner lock changes retain the guards. A late owned acquisition is released and removes the guards; a late error removes the guards without changing disposed state. Promise requests use their settlement closure after disposal and retain no document listeners. The disposed instance cannot request, accept mouse movement, notify a later state, or reactivate.

Assertions cover the `waiting` feedback, no second native call or look input while waiting, no autoqueue, explicit fresh gesture after settlement, other-owner lock preservation, owned late-lock release, ordinary-listener removal, terminal guard cleanup, and the permanent disposed state.
