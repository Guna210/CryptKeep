## Correction

`createWorldRenderer` now documents exclusive ownership of its supplied WebGL2 context. Its idempotent `dispose()` disconnects its `ResizeObserver`, disposes owned geometry/materials and the Three.js renderer, then calls the public `renderer.forceContextLoss()` API to retire the context and invalidate remaining native handles, including renderer-internal texture allocations. The renderer leaves the canvas element in the DOM. Any later renderer must receive a fresh caller-owned canvas and new context.

The isolated browser fixture now instruments `createTexture` on each individual test context and retains the returned native texture handles. For each teardown it verifies `isContextLost()` and checks every tracked handle with `isTexture()`. It verifies all old contexts are lost before the replacement becomes the only live context, then checks that replacement renders and owns valid handles. The test observes that renderer disposal leaves the canvas in place; the test caller removes it before constructing the replacement. Observer cleanup, idempotent disposal, stable canvas count, viewport resize/aspect, visible rendering, fallback behavior, and page/console errors remain covered. No production debug hooks were added.
