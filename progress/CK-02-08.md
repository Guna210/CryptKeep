# CK-02-08 — Implement pause and focus-loss session behavior

**Builder/model:** `/root/ck_02_08_builder` / GPT-6 Luna

**Status:** **SUBMITTED** for independent review. No Git operations were performed.

## Result

Added an app-owned `PauseCoordinator` for loading, initial availability, active play, pause, capture request/wait, unavailable generation failure, unsupported rendering, and disposal. It receives the accepted `PlayerSession` pointer-capture state and its existing optional reason. It does not own pointer lock, a clock, or an animation loop. Initial Explore remains available until the first successful capture. After that, active play hides the initial setup panel and Escape, blur, hidden-page, editable-focus, or native lock loss opens a compact accessible panel with a reason and a keyboard-operable Resume button. The existing seed form remains reachable while paused so players can reroll the floor; a successful reroll remains paused until a new Resume gesture.

Resume and initial Explore both call the existing native `requestFromGesture` directly in their trusted click handler. The floor and player resume only after the capture callback confirms the surface owns native lock, readiness is `ready`, and the document is visible. Denied capture remains paused with a retry prompt. Waiting for a canceled outstanding native request is shown and requires another gesture after it settles. Focus and visibility restoration do not resume play. Floor rerolls enter loading, release capture and stop input, and return to available/paused only after the load outcome; generation success never auto-resumes.

The existing `PlayerSession` still clears input, stops velocity, cancels active dash/evasion while preserving paid stamina/cooldown, and delegates pause/resume timestamps to the same `FloorSession` clock. Its capture callback now forwards the already-provided optional reason. Pagehide teardown disposes player/capture first, then the pause coordinator and its DOM listener, then floor/renderer/diagnostics/shell. The pause panel screenshot was generated by the native Chromium test and visually inspected.
