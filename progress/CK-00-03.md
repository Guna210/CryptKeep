## Scope and implementation

Implemented an owned Three.js renderer in `src/render/renderer.ts`, connected it through the existing canvas/context in `src/main.ts`, and moved buffer sizing/resizing from the shell to a `ResizeObserver` owned by the renderer. `createWorldRenderer(canvas, { context, resizeTarget, fov? })` returns the reusable `scene`, `camera`, `renderer`, renderer resource counts, and idempotent `dispose()`. The renderer has exclusive ownership of its supplied WebGL2 context and retires it on disposal; callers must create a fresh canvas/context before constructing a replacement renderer. The renderer leaves canvas DOM ownership with its caller. The shell remains the sole creator of its canvas and presents the existing readable WebGL 2 fallback if context acquisition or renderer initialization fails.

The rendered fixture contains a ground plane, box props, a tapered landmark, two pillars, and directional lighting. Its logical buffer is capped at 480×270 and follows the viewport aspect; the camera projection follows the displayed viewport. DOM text remains sharp. The production page says “Dungeon preview” and does not expose the fixture's resource diagnostics. Browser lifecycle tests use the labeled temporary Vite fixture in `tests/harness/`.

## Round-1 repair

Finding `CK-00-03-R1-F01` identified context-wide native texture accumulation hidden by per-renderer `renderer.info` counts. The repair calls Three.js' public `renderer.dispose()` and `renderer.forceContextLoss()` during idempotent teardown. The API now documents exclusive context ownership and requires a new caller-owned canvas/context for every subsequent renderer. The browser fixture instruments only each test context's `createTexture` method, retains returned native handles, and checks context loss plus handle invalidation before it removes the old canvas and creates a fresh renderer. It also checks replacement rendering, observer cleanup, canvas ownership and DOM stability. The original review report is preserved; its same-reviewer verification passed as recorded below.

The preview is a diagnostic geometry scene, not a generated dungeon or playable game. GPU counts are from headless system Chromium/software rendering and do not measure target-device performance or total driver memory. Context loss is used to prove native resource invalidation; explicit `deleteTexture` counts are not used as a proxy for released resources.
