# CK-02-02 — Implement normalized planar locomotion

**Builder/model:** `/root/ck_02_02_builder` / GPT-6 Luna

## Result and scope

Added a pure yaw-relative locomotion step that normalizes diagonal input, moves only in world X/Z, and applies bounded acceleration or deceleration using explicit seconds. Walking defaults to 3.5 m/s, acceleration to 24 m/s², and deceleration to 32 m/s². These acceleration values are implementation defaults and remain tunable. Inactive state immediately zeros planar velocity. No sprint, dash, collision, DOM, Three.js, or browser integration was added.

Changed owned paths: `src/player/movement.ts`, `src/player/movement.test.ts`, and this handoff. `CONTEXT.md` had an existing orchestrator change and was preserved. No Git operations were performed.

## Interface and behavior

- `stepLocomotion(player, axes, dtSeconds, options?)` returns a frozen `LocomotionStep` with an immutable candidate `state` and requested X/Z `displacement` in metres. The candidate pose advances without collision resolution; the collision task should resolve the displacement before committing the position.
- Axes use `x` for right and `y` for forward. Input length above one is normalized; nonfinite axes become zero. At yaw zero, forward is world −Z and right is +X. Positive yaw rotates forward toward −X. Pitch is ignored.
- `dtSeconds` is in seconds and must be finite and positive. Nonfinite or nonpositive dt and unrepresentable world-coordinate results throw `RangeError`; no clock or wall-time source is read.
- Options expose bounded `maxSpeed`, `acceleration`, and `deceleration` values for future movement modifiers. Setting `active: false` immediately clears velocity and returns zero displacement, so inactive/menu screens cannot inherit motion.
- `WALK_SPEED_METERS_PER_SECOND`, `DEFAULT_ACCELERATION_METERS_PER_SECOND_SQUARED`, and `DEFAULT_DECELERATION_METERS_PER_SECOND_SQUARED` provide the named defaults.
